1. mc_mode

<code>mc_mode()</code> is a teaching implementation of the mode, which base R does not provide. It returns every value tied for the highest frequency, so data with several modes is handled correctly instead of returning only one.
Purpose: find the value(s) with the highest frequency (the mode). Base R has no built-in mode function, so this is a teaching-oriented reimplementation. Arguments: x accepts a numeric or factor vector; na.rm controls whether missing values are removed before counting (default TRUE, so NAs are excluded from the frequency tally). Result: returns every value tied for the highest frequency, so multimodal data is handled naturally — a bimodal distribution returns both modes; the return type matches the input (numeric input yields a numeric vector). Note: if every value occurs exactly once, all values are treated as modes and returned as-is, which is usually meaningless; run mc_inspect() first to understand the distribution. Returns NULL when all observations are missing.

Arguments

xA numeric or factor vector.

Value

A vector of all mode(s), coerced back to the input type; <code>NULL</code> when there are no non-missing values.

Example

# Chapter 3: low birthweight study dataset (birthwt, MASS)
birthwt <- MASS::birthwt
mc_mode(factor(birthwt$race))     # most common race category (1 = white)
mc_mode(factor(birthwt$smoke))    # mode of smoking status (0 = non-smoker)
mc_mode(c(NA, NA, 1, 2), na.rm = FALSE)   # returns "NA" when NA present

2. mc_inspect

One row per column: the column <code>class</code>, number of observations <code>n</code>, count of missing values <code>n_missing</code>, missing percentage <code>pct_missing</code>, and number of unique values <code>n_unique</code>. Handy for a quick data-quality check before modelling.
Purpose: a quick pre-modelling data-quality check; for each column it reports the type, number of observations, number of missing values, missing percentage and number of unique values. Arguments: .data is a data.frame or tibble; no other arguments. Result: returns a data.frame with one row per input column. Columns: variable (column name), class (type), n (valid observations), n_missing (missing count), pct_missing (missing percentage), n_unique (number of unique values). Note: n is the count of valid (non-missing) observations, so n + n_missing equals the column's total length, and the missing percentage is computed against that total length. This is the first "health check" of the preprocessing pipeline — run it before any cleaning or modelling.

Value

A <code>data.frame</code> with those six columns, one row per input column.

Example

# Chapter 1: data-quality check on the birthwt data frame (try injecting
# missing values to practice)
birthwt <- MASS::birthwt
mc_inspect(birthwt[, c("age", "lwt", "bwt", "smoke", "low")])

3. mc_theme

A light, restrained ggplot2 theme with ample whitespace, ready for direct use in reports. It is the default theme returned inside the <code>plot</code>/<code>forest</code> components of several analysis functions (e.g. <code>mc_survfit()</code>, <code>mc_cox()</code>, <code>mc_rcs()</code>).
Purpose: a light, restrained ggplot2 theme with ample whitespace for report figures, matching the plot components returned by several analysis functions (e.g. mc_survfit(), mc_cox(), mc_rcs()). Arguments: base_size controls the base font size; default 12. Result: returns a ggplot2 theme object that can be appended to any ggplot with +. Note: this is a pure theme (no geoms), so it must be combined with layers such as geom_point() or geom_line(); pair it with mc_palette() to change the colour scheme.

Value

A <code>ggplot2</code> theme object, usable with <code>+</code>.

Example

library(ggplot2)
# Chapter 3: maternal pregnancy weight vs. birth weight scatter
# (coloured by smoking status)
birthwt <- MASS::birthwt
p <- ggplot(birthwt, aes(lwt, bwt, color = factor(smoke))) +
  geom_point(size = 2, alpha = 0.6) + mc_theme(base_size = 13)
print(p)

4. mc_palette

Supplies a set of stable brand anchor colours (hex) and, instead of a static vector, linearly interpolates between anchors to generate any number of transition colours (a continuous gradient or a discrete ramp). Returns a named character vector usable with <code>ggplot2::scale_color_manual()</code> / <code>scale_fill_manual()</code>.
Purpose: returns the brand anchor colours to keep plotting colours consistent; when the number of categories exceeds 6, it interpolates between anchors to generate the required number of colours, avoiding manual colour picking. Method (original): internally it parses "#RRGGBB" into a 0-255 RGB triplet (.hex_to_rgb), performs linear interpolation between anchor colours by position (.interp_palette), then converts the result back to hex (.rgb_to_hex); the whole process uses no palette package. Arguments: n is the number of colours to generate; NULL (default) returns the six fixed brand colours. type selects "brand" (default, six discrete brand colours), "gradient" (continuous gradient between brand colours, default 100 colours), or "discrete" (a discrete ramp interpolated over the brand colours). Result: by default returns a named character vector with the six brand colours: primary (blue), secondary (purple), accent (green), warn (red), info (cyan), muted (grey). When n is given, returns a colour vector of length n (gradient is unnamed by default; discrete/brand keep anchor names). Note: colours are generated purely algorithmically with no dependence on data; interpolation is in linear RGB space — switch to HCL space later if a more perceptually uniform ramp is needed. Often paired with mc_theme() for style-consistent report figures.

Value

A named character vector of the six brand colours by default, or a vector of length <code>n</code>.

Example

pal <- mc_palette()                 # default: six brand colours
print(pal)
grad <- mc_palette(n = 20, type = "gradient")  # 20-colour continuous gradient
print(head(grad))
library(ggplot2)
df <- data.frame(name = factor(names(pal), names(pal)), col = pal)
p <- ggplot(df, aes(name, fill = name)) + geom_bar() +
  scale_fill_manual(values = pal) + theme_void()
print(p)

5. mc_impute_knn

Corresponds to Chapter 2 ("KNN imputation"). Imputes only numeric columns using standardised Euclidean distance; missing values in non-numeric columns are left untouched with a warning. No extra dependency is required.
Purpose: Impute missing values in numeric columns using K-nearest neighbours, suitable when missingness is low and variables are correlated. Method: Only numeric columns are processed. Columns are standardised (mean-centred, divided by SD), then for each missing point the k nearest non-missing observations are found by Euclidean distance and their mean is used to impute; columns with zero SD fall back to column-mean imputation. Missing values in non-numeric columns are left untouched with a warning. Arguments: <code>.data</code> is a data.frame; <code>k</code> is the number of neighbours, default 5. Result: Returns an imputed data.frame with the same structure as the input. Note: KNN is sensitive to scale, so standardisation is done internally; however, if columns differ greatly in range, it is still recommended to run mc_scale() first. Categorical variables are not used in KNN and must be handled separately (e.g. mode imputation or category merging).

Value

The imputed <code>data.frame</code> (same structure as the input).

Example

# Chapter 2: demonstrating KNN missing-value imputation with iris
data(iris)
set.seed(105)
iris_na <- iris
iris_na$Sepal.Length[sample(150, 15)] <- NA
iris_na$Sepal.Width[sample(150, 15)] <- NA
head(mc_impute_knn(iris_na, k = 3))

6. mc_impute_mice

Corresponds to Chapter 2 ("multiple imputation by chained equations"). Requires the mice package (Suggests). On top of the MICE engine, it adds an original per-variable imputation diagnostic.
Purpose: Use multiple imputation by chained equations (MICE) to handle missingness, suitable when the missingness mechanism is complex and you want to retain uncertainty; it also provides a quantitative per-column imputation diagnostic afterwards. Dependency: Requires the mice package (Suggests); an informative error is raised if it is not installed. Method: For each variable with missingness, related variables are used as predictors in an iterative model that generates multiple complete datasets, preserving the uncertainty due to missingness. Arguments: <code>.data</code> is a data.frame; <code>m</code> is the number of imputations (datasets generated), default 5; <code>method</code> of NULL means automatic selection; <code>...</code> is passed to mice::mice(). Result: Returns a list containing <code>mids</code> (the raw multiple-imputation object for further analysis), <code>long</code> (the long table from mice::complete(action = "long")), and <code>summary</code> — an original diagnostic table: per variable it gives <code>n_missing_original</code> (original missing count), <code>n_imputed</code> (count of imputed observations), and <code>pct_imputed</code> (imputation proportion). Note: Analysis after multiple imputation should not rely on a single dataset; instead use the <code>mids</code> object with downstream functions supporting mice (e.g. with()/pool()) to pool results. The <code>summary</code> is only for quickly checking which variables were imputed and by how much, and does not represent imputation quality itself.

Value

A list with <code>mids</code>, <code>long</code>, and <code>summary</code>: <code>mids</code> is the raw <code>mids</code> object, <code>long</code> is the imputed long table (from <code>mice::complete(action = "long")</code>), and <code>summary</code> is the per-variable imputation diagnostic table.

Example

# Chapter 2: multiple imputation by chained equations (MICE) with per-variable diagnostic
set.seed(106)
n <- 44
df <- data.frame(
  age  = c(rnorm(n - 4, 50), NA, NA, rnorm(2, 55)),
  bili = c(NA, rnorm(n - 4, 1.2), NA, rnorm(2, 1.5)),
  chol = rnorm(n, 200, 40), stringsAsFactors = FALSE)
res <- mc_impute_mice(df, m = 3)
head(res$long)
print(res$summary)   # original: per-variable imputation diagnostic

7. mc_dedup

Corresponds to Chapter 2 ("deduplication"). Deduplicates by all columns by default, or by specified key columns, keeping the last row of each group.
Purpose: Remove duplicate rows, commonly used to clean duplicate entries or repeated follow-up records. Arguments: <code>.data</code> is a data.frame; <code>by</code> names the key columns used to detect duplicates (e.g. subject ID), NULL means judge by all columns; <code>keep</code> chooses whether to retain the "last" (default) or "first" row of each group. Result: Returns the deduplicated data.frame. Note: When <code>by</code> is specified, only those key columns are compared; other columns are ignored even if they differ, and duplicates are collapsed to a single row. Ensure the key columns uniquely identify a record, or information may be lost. This matches Excel's "Remove Duplicates" semantics.

Value

The deduplicated <code>data.frame</code>.

Example

# Chapter 2: removing duplicate follow-up records (deduplicate by subject ID)
df <- data.frame(subj = c(1, 1, 2, 2, 3), measure = c("a", "a", "b", "b", "c"), visit = 1:5)
mc_dedup(df, by = "subj")                  # keep the last row of each group
mc_dedup(df, by = "subj", keep = "first")  # keep the first row of each group

8. mc_scale

Corresponds to Chapter 2 ("feature scaling"). Supports z-score (default), min-max, and robust (median/IQR based) scaling. Only numeric columns are replaced.
Purpose: Scale numeric columns to remove scale differences, speed up model convergence, or prepare data for algorithms such as KNN or regularised regression. Method: Three scaling options — z (default; z-score: subtract mean, divide by SD, yielding mean 0 and SD 1), minmax (linear transform to {0, 1}), and robust (subtract median, divide by IQR; robust to outliers). Arguments: <code>.data</code> is a data.frame; <code>cols</code> names the columns to scale, NULL means all numeric columns; <code>method</code> selects one of the three above. Result: Returns a data.frame where only numeric columns are replaced; other columns are unchanged. Note: Scaling discards the original units, so model coefficients are harder to interpret in real units; if interpretability is needed, keep the original variables or record the scaling parameters for back-transformation. Missing values are excluded column-wise when computing scaling.

Value

The scaled <code>data.frame</code>; only numeric columns are replaced.

Example

# Chapter 2: scaling numeric columns of iris (removing scale differences)
mc_scale(iris[, 1:4], method = "z")        # z-score standardisation
mc_scale(iris[, 1:4], method = "minmax")   # normalise to [0, 1]
mc_scale(iris[, 1:4], method = "robust")   # robust scaling

9. mc_wide_long

Pivots the specified measure columns of a wide table into a long layout. Implemented natively in base R with no external pivoting dependency.
Purpose: Convert a wide table (multiple measurements of one subject in different columns) to a long table (one row per measurement); a core step in data processing. Method (original, native implementation): First verify that <code>id_cols</code> and <code>measure_vars</code> exist in the data.frame; then for each measure column, replicate and stack the identifier columns by the number of measure columns, and merge each measure column name as the "variable" and its values as the "value", producing a tidy long table. Uses only base R with no external dependency. Arguments: <code>.data</code> is a data.frame; <code>id_cols</code> are the identifier columns to keep (e.g. ID, group); <code>measure_vars</code> are the measure columns to lengthen; <code>name_to</code>/<code>value_to</code> are the output column names for "variable" and "value", defaulting to variable / value. Result: Returns a long-format data.frame. Note: After conversion, rows = original rows x number of measure columns; this is the inverse of mc_long_wide(). If measure columns carry time suffixes (e.g. t1/t2/t3), the result is a tidy "time-value" pair of columns, convenient for repeated-measures analysis. Identifier columns that are factors are preserved as factors; measure columns should share a common type, otherwise the "value" column is coerced to a common type.

Arguments

id_colsIdentifier columns to keep.
measure_varsMeasured columns to pivot longer.

Value

The long <code>data.frame</code>.

Example

# Chapter 2: convert wide table of longitudinal blood-pressure measurements to long (t1/t2/t3 visits)
wide <- data.frame(id = 1:4,
  t1 = rnorm(4, 120), t2 = rnorm(4, 122), t3 = rnorm(4, 118))
mc_wide_long(wide, id_cols = "id", measure_vars = c("t1", "t2", "t3"))

10. mc_long_wide

Spreads a long table back to wide. Implemented natively in base R with no external pivoting dependency.
Purpose: Spread a long table back to wide by the name column; the inverse of mc_wide_long(), commonly used to restore a "time-value" long table to a subject x time-point wide matrix. Method (original, native implementation): First take the unique combinations of identifier columns as the skeleton of output rows; then for each value of the name column, fill the corresponding <code>value_from</code> back into the new column according to the "identifier key -> value" relationship. Spreading is done via custom key concatenation and matching, relying only on base R. Arguments: <code>.data</code> is the long table; <code>id_cols</code> are the identifier columns; <code>name_from</code> is the source column supplying new column names; <code>value_from</code> is the source column supplying fill values. Result: Returns a wide-format data.frame. Note: If duplicate (identifier + name) combinations exist (same ID and name appearing multiple times), the spread takes the first occurrence and issues a warning; ensure identifier + name is unique before converting. This is the inverse of mc_wide_long().

Arguments

id_colsIdentifier columns.
name_fromColumn providing names.
value_fromColumn providing values.

Value

The wide <code>data.frame</code>.

Example

# Chapter 2: restore a "visit-blood pressure" long table to a subject x visit wide table
long_df <- data.frame(id = 1:2, variable = c("t1", "t2"),
                      value = c(120, 118))
mc_long_wide(long_df, id_cols = "id",
  name_from = "variable", value_from = "value")

11. mc_desc_quant

Corresponds to Chapter 3 of Part 2: produces about 20 descriptive statistics in one call (n, n missing, mean, median, sd, variance, min, max, range, IQR, SE, 95% CI, CV, skewness, kurtosis, Shapiro-Wilk normality). Supports grouped computation.
Purpose: one-call descriptive statistics for quantitative variables, covering about 20 common metrics; the main function for baseline tables and pre-modeling exploration. Arguments: <code>.data</code> is a data frame; <code>vars</code> selects the numeric columns to describe (all numeric columns by default); <code>group</code> optionally specifies a grouping column for per-group output; <code>conf</code> is the confidence level for the mean, default 0.95. Result: returns a data frame with sample size, mean, sd, median, IQR, min, max, skewness, kurtosis, normality-test statistics, and the mean confidence interval. Note: skewness/kurtosis help judge distribution shape (skewness far from 0 or kurtosis much greater than 3 suggests non-normality); if planning t-tests/ANOVA, check normality and variance homogeneity first. When grouping, group sizes may differ, so mind the fairness of comparisons.

Arguments

groupOptional grouping variable name.

Value

A wide <code>data.frame</code>, one row per variable (one row per group level when grouped), with columns <code>variable</code>, <code>group</code> (when grouped), and the 18 statistic columns.

Example

# Chapter 3: low birth weight study (birthwt, MASS package)
birthwt <- MASS::birthwt
cat("==== Overall: birth weight / age / pregnancy weight ====\n")
print(mc_desc_quant(birthwt, vars = c("bwt","age","lwt")), row.names = FALSE)
cat("\n==== Grouped by mother's smoking status ====\n")
print(mc_desc_quant(birthwt, vars = c("bwt","age"), group = "smoke"), row.names = FALSE)

12. mc_norm_test

Corresponds to Chapter 3: Shapiro-Wilk (default, robust for n <= 5000) or Kolmogorov-Smirnov. Returns the test name, statistic and p-value.
Purpose: test whether a quantitative variable follows a normal distribution; a prerequisite for choosing parametric vs non-parametric methods. Methods: <code>shapiro</code> (default) is the Shapiro-Wilk test, sensitive and powerful for small-to-moderate samples (typically n < 5000); <code>ks</code> is the Kolmogorov-Smirnov test, by default compared against the standard normal, sensitive to location/scale. Arguments: <code>x</code> is the numeric vector to test; <code>method</code> selects one of the two. Result: returns the test statistic, p-value, etc. Note: with large samples normality tests easily become "significant" (tiny p) even when deviation is practically harmless, so do not rely on p alone—combine with histograms, Q-Q plots and skewness/kurtosis. The Shapiro test may be unreliable or very slow for n > 5000.

Arguments

xNumeric vector.

Value

A <code>data.frame</code> with columns <code>test</code>, <code>statistic</code>, <code>p.value</code>.

Example

# Chapter 3: test whether quantitative variables in birthwt are normal
birthwt <- MASS::birthwt
mc_norm_test(birthwt$bwt)         # birth weight
mc_norm_test(birthwt$age)         # mother's age

13. mc_var_test

Corresponds to Chapter 3 ("three methods for variance homogeneity"): Bartlett, Fligner-Killeen, and Levene (mean-deviation method). Returns the test name, statistic and p-value.
Purpose: test whether several groups have equal population variances (variance homogeneity), a prerequisite before choosing ANOVA / t-tests (which usually assume equal variance). Methods: <code>bartlett</code> (default) is most sensitive for normal data; <code>fligner</code> (Fligner-Killeen) is robust to non-normality; <code>levene</code> (Levene) is based on deviations and robust to heavy-tailed distributions, the most commonly used. Arguments: <code>x</code> is a numeric vector; <code>g</code> is the grouping factor/vector (same length as <code>x</code>); <code>method</code> selects one of the three. Result: returns the test statistic, degrees of freedom and p-value. Note: if variances are unequal (small p), use Welch correction (e.g. mc_ttest defaults to Welch for two samples) or a non-parametric method instead of the standard t-test/ANOVA. Bartlett relies strongly on normality; for non-normal data prefer Levene or Fligner.

Arguments

xNumeric vector.
gA grouping factor.

Value

A <code>data.frame</code> with columns <code>test</code>, <code>statistic</code>, <code>p.value</code>.

Example

# Chapter 3: test variance homogeneity of birth weight across races (race)
birthwt <- MASS::birthwt
mc_var_test(birthwt$bwt, birthwt$race, method = "bartlett")
mc_var_test(birthwt$bwt, birthwt$race, method = "levene")

14. mc_ttest

Corresponds to Chapter 3: one-sample, independent two-sample, and paired t-tests through a single entry point.
Purpose: a unified entry point for t-tests covering three common cases: one-sample (vs a known constant), independent two-sample, and paired. Methods: two independent samples use Welch's corrected t-test by default (no equal-variance assumption), closer to practice; can switch to Student's t. Arguments: <code>x</code> is the first group or one-sample vector; <code>y</code> is the second vector (for independent/paired; left NULL for one-sample); <code>paired = TRUE</code> runs a paired t-test; <code>mu</code> is the reference value for the one-sample test, default 0; <code>conf</code>/<code>alternative</code> control confidence level and the alternative direction. Result: returns the mean difference (or sample mean), standard error, t statistic, degrees of freedom, p-value and confidence interval. Note: paired tests require x, y to be paired (e.g. same person measured before/after); using an independent test when groups are not independent understates error. For clearly skewed or small samples, consider mc_nonparam()'s Wilcoxon test.

Arguments

xNumeric vector.

Value

A <code>data.frame</code> with columns <code>method</code>, <code>estimate</code>, <code>conf.low</code>, <code>conf.high</code>, <code>statistic</code>, <code>p.value</code>.

Example

# Chapter 3
birthwt <- MASS::birthwt
# One-sample: is the average birth weight equal to 3000 g?
mc_ttest(birthwt$bwt, mu = 3000)
# Independent two-sample (Welch correction): smoking vs non-smoking mothers' birth weight
mc_ttest(birthwt$bwt[birthwt$smoke == 1], birthwt$bwt[birthwt$smoke == 0])

15. mc_anova

Corresponds to Chapter 3 ("ANOVA"). Built on <code>stats::aov</code>, returns the degrees of freedom, sum of squares, mean square, F statistic and p-value of each term.
Purpose: one-way ANOVA, comparing whether the means of three or more groups are equal overall. Methods: decomposes variation via a linear model, comparing between-group and within-group mean squares to obtain the F statistic. Arguments: <code>formula</code> like y ~ g (response ~ grouping factor); <code>data</code> is the data frame containing both columns. Result: returns the degrees of freedom, sum of squares, mean square, F value and p-value of each term. Note: ANOVA only tells you "at least two groups differ"; which two require post-hoc multiple comparisons (e.g. Tukey HSD). Its assumptions are normality and equal variance per group—verify first with mc_norm_test() and mc_var_test(). If variances are unequal or distributions skewed, consider Kruskal-Wallis (see mc_nonparam).

Value

A <code>data.frame</code> with columns <code>term</code>, <code>df</code>, <code>sumsq</code>, <code>meansq</code>, <code>statistic</code>, <code>p.value</code>.

Example

# Chapter 3: do mothers of different races (race) differ in birth weight? (one-way ANOVA)
birthwt <- MASS::birthwt
mc_anova(bwt ~ factor(race), data = birthwt)

16. mc_nonparam

Corresponds to Chapter 3 ("non-parametric tests between groups"): Wilcoxon rank-sum (two groups) or Kruskal-Wallis (multiple groups). Returns the test name, statistic and p-value.
Purpose: when data violate normality/equal-variance assumptions, or are merely ordinal, use non-parametric methods to compare groups. Methods: <code>wilcoxon</code> is the Wilcoxon rank-sum test (Mann-Whitney U) for two independent samples; <code>kruskal</code> is the Kruskal-Wallis test for three or more groups. They compare distribution location (ranks), not means. Arguments: <code>x</code> is a numeric vector; <code>g</code> is the grouping vector (wilcoxon for two groups, kruskal for multiple); <code>method</code> selects the test. Result: returns the test statistic and p-value (Kruskal also includes df). Note: non-parametric tests usually have lower power than their parametric counterparts (when data are truly normal) but are more robust; they test "whether distributions are identical / locations shifted", so conclusions should be phrased as "median/distribution difference" not "mean difference". For paired two groups use the Wilcoxon signed-rank test (not covered here; use stats::wilcox.test(paired = TRUE)).

Arguments

xNumeric vector.
gGrouping vector/factor.

Value

A <code>data.frame</code> with columns <code>test</code>, <code>statistic</code>, <code>p.value</code>.

Example

# Chapter 3: birth weight by smoking status (two-group Wilcoxon) and race (multi-group Kruskal-Wallis)
birthwt <- MASS::birthwt
mc_nonparam(birthwt$bwt, birthwt$smoke, method = "wilcoxon")
mc_nonparam(birthwt$bwt, factor(birthwt$race), method = "kruskal")

17. mc_contingency

Corresponds to Chapter 4, Section 4.3 (chi-square, Fisher's exact, and the Cochran-Mantel-Haenszel test). Builds a contingency table and runs one of three independence tests selected by <code>method</code>.
Purpose: build contingency tables for categorical variables and run independence/association tests; the first step in analyzing categorical associations, covering the three methods required by Section 4.3. Methods: { item <code>"chisq"</code> (default): chi-square independence test for 2x2 and larger tables; <code>correct = TRUE</code> applies Yates' continuity correction to 2x2 tables to avoid overstating significance in small samples. For 2x2 tables, Fisher's exact method additionally gives the OR and its 95% CI. item <code>"fisher"</code>: <code>stats::fisher.test</code> exact test for any r x c table (suitable for small samples or sparse expected counts). item <code>"cmh"</code>: requires a <code>strata</code> variable; builds a 3-way contingency table and runs <code>stats::mantelhaen.test</code> (Cochran-Mantel- Haenszel) to judge whether the row-column association persists after controlling for the stratifying factor, returning the common OR. } Arguments: <code>.data</code> is a data frame; <code>row</code>/<code>col</code> are the row/column variable names; <code>correct</code> controls chi-square continuity correction; <code>method</code> selects the test type; <code>strata</code> is the layer variable name for CMH. Result: returns a list with table (contingency table, stratified when 3-way), test (a data frame: test/statistic/df/p.value), and method-specific OR / commonOR. Note: chi-square requires sufficiently large expected counts (generally a sufficient proportion of cells with expected > 5), otherwise use <code>method = "fisher"</code>. CMH is suitable for estimating "adjusted" association when there is a confounding stratum (e.g. multi-center studies). OR > 1 suggests a positive association; a CI crossing 1 means the association is not significant.

25. mc_model_compare

Corresponds to Chapter 5 (5.8, comparing multiple models). Computes AIC, BIC, a self-implemented small-sample-corrected AICc and Akaike weights from AICc, then ranks models by weight.

Arguments

Value

A ranked comparison table sorted by Akaike weight.

Purpose: Use restricted cubic splines (RCS) to describe the non-linear dose-response relationship between a predictor and the outcome, and to visualize the curve; a common approach in epidemiology for presenting exposure-effect curves. Method: A self-implemented spline basis (no extra dependencies) applies linear constraints at both ends of the predictor ("restricted") to avoid wild swings at the boundaries; default interior knots <code>nk = 3</code>. Arguments: <code>data</code> is a data frame; <code>x</code> is the predictor column name; <code>y</code> is the response column name; <code>nk</code> is the number of knots (default 3, larger = more flexible); <code>knots</code> can manually set knot positions (default auto-selected by quantiles); <code>family</code> defaults to gaussian and also supports binomial (then it describes how the log-odds change with x). Results: Returns a list with <code>knots</code> (knot positions), <code>coefficients</code> (spline basis coefficients), and <code>plot</code> (prediction-curve ggplot object). Notes: More knots make the curve wigglier and more prone to overfitting; usually 3-5 knots suffice. RCS does not assume monotonicity and can show U-shaped or inverted-U relationships. View the result with <code>print(res$plot)</code>.

Arguments

xNumeric predictor name.
yResponse variable name.

Value

A list with <code>model</code>, <code>coefficients</code>, <code>plot</code>, <code>knots</code>.

Example

# Chapter 7: dose-response curve of maternal age vs low-birth-weight risk (non-linear)
birthwt <- MASS::birthwt
res <- mc_rcs(birthwt, x = "age", y = "low", nk = 4, family = "binomial")
cat("knots:", round(res$knots, 2), "\n")
print(res$plot)

34. mc_quantile_reg

Corresponds to Chapter 7 "Principles and Application Scenarios of Quantile Regression" of the routine medical-data-science tutorial. Built on code{{rq}}, it returns coefficients for multiple quantiles at once.
Purpose: Use quantile regression to describe how a predictor affects different quantiles of the outcome (e.g. median, upper/lower quartiles); especially useful under heteroscedasticity or when focusing on extreme quantiles (e.g. low income, high death risk). Method: Based on quantreg's <code>rq()</code>, minimizing weighted absolute residuals; it can estimate coefficients for multiple quantiles at once. Arguments: <code>data</code> is a data frame; <code>formula</code> is of the form <code>y ~ x</code>; <code>taus</code> is the vector of quantiles to estimate, default <code>c(0.25, 0.5, 0.75)</code>. Results: Returns a data frame of coefficients at each quantile (including intercept and predictor slope), allowing comparison of slopes across quantiles. Notes: If the predictor slope differs markedly across quantiles (e.g. under heteroscedasticity), the conditional distribution shape changes with x -- information invisible to ordinary mean regression (OLS). Quantile regression is robust to outliers. Depends on quantreg (Suggests).

Arguments

formulaA regression formula.

Value

A <code>data.frame</code> with columns <code>term</code>, <code>estimate</code>, <code>std.error</code>, <code>statistic</code>, <code>p.value</code>, <code>tau</code> (stacked over taus).

Example

# Chapter 7: conditional quantile regression of birth weight (slope of pregnancy weight lwt across quantiles)
birthwt <- MASS::birthwt
mc_quantile_reg(birthwt, bwt ~ lwt + age, taus = c(0.25, 0.5, 0.75))

35. mc_pcr

Corresponds to Chapter 7 (7.8, PCR). The whole pipeline is self-implemented: PCA via <code>stats::prcomp</code>, an in-house k-fold CV to pick the number of components, and a back-transform of coefficients to the original scale.
Purpose: When predictors are highly correlated (multicollinear), use principal components regression for stable estimation. Method (self-implemented): (1) standardize predictors (center + scale); (2) PCA yields uncorrelated principal components; (3) if the number of components is not given, an in-house k-fold CV selects the optimum by prediction MSE; (4) fit linear regression on the selected components; (5) back-transform component coefficients to the original variable scale (using the rotation matrix and standardization parameters). Arguments: <code>data</code> is a data frame; <code>formula</code> is of the form <code>y ~ x1 + x2 + ...</code>; <code>ncomp</code> is the number of components (<code>NULL</code> = auto-selected by CV); <code>k</code> is the number of CV folds (default 5); <code>seed</code> is the CV random seed. Results: Returns a list -- <code>best_ncomp</code> (chosen components), <code>cv_table</code> (CV-MSE for each candidate), <code>coef_original</code> (original-scale coefficients + intercept), <code>performance</code> (R-squared / adjusted R-squared / RMSE), <code>plot</code> (CV-MSE vs number of components), <code>fit</code> (final lm object). Notes: PCR standardizes predictors, so coefficients relate to the standardized scale; categorical variables should be dummy-coded first. This function depends only on base R, no extra package needed.

Arguments

seedRandom seed for CV.

Value

A list with chosen components, CV table, original-scale coefficients, performance and the CV plot.

Example

# Chapter 7, Section 7.8: predict birth weight from several correlated predictors (PCR removes collinearity)
# Note: PCR requires all predictors to be numeric, so the categorical variable race is
# excluded (dummy-coding is discussed elsewhere)
birthwt <- MASS::birthwt
bw <- birthwt
res <- mc_pcr(bw, bwt ~ age + lwt + smoke + ht + ui + ptl, k = 5, seed = 1)
res$best_ncomp
res$coef_original
print(res$plot)

37. mc_competing_risk

Corresponds to Chapter 8 ("competing-risk survival analysis"). Based on cmprsk's <code>crr</code>. <code>status</code>: 0 = censored, >0 = different event types; <code>cause</code> selects the event of interest.
Purpose: Perform regression in the presence of competing events, avoiding overestimation of the target-event risk by mistakenly treating competing events as censored. Typical scenario: a relapse analysis where death is the competing event. Method: Based on cmprsk's Fine-Gray subdistribution-hazard model, which treats competing events as a special kind of censoring and directly estimates the cumulative incidence of the target cause. Arguments: <code>data</code> is a data frame; <code>time</code> is the time column; <code>status</code> is the status column (0 = censored, >0 = different event types); <code>group</code> is the grouping/exposure variable; <code>cause</code> specifies the target event code (default 1). Results: Returns a list with <code>coefficients</code> (subdistribution hazard ratio SHR, SE, z, p value per variable). Notes: The <code>status</code> coding differs from <code>mc_survfit()</code>/<code>mc_cox()</code>: here 0 is censored and each other positive integer represents one event type; arrange the data accordingly. If there is only one event type with no competition, an ordinary Cox model suffices. Depends on cmprsk (Suggests).

Arguments

timeTime variable name.
statusCompeting-risk status variable name.
groupCovariate (grouping/exposure) variable name.

Value

A list with <code>model</code> (crr object), <code>coefficients</code> (subdistribution HR table: variable / HR / coef / p.value).

Example

# Chapter 8, Section 8.2: competing risks of leukemia relapse (1) and death (2)
# Event of interest cause = 1 (relapse); death is a competing event and must not be treated as censored
set.seed(126)
n <- 300
trt     <- sample(c(0,1), n, TRUE)
ftime   <- rexp(n, .05)
fstatus <- sample(0:2, n, TRUE, c(.4,.35,.25))   # 0 censored, 1 relapse, 2 death (competing)
df <- data.frame(ftime = ftime, fstatus = fstatus, trt = trt)
res <- mc_competing_risk(df, time = "ftime", status = "fstatus", group = "trt", cause = 1)
print(res$coefficients)

38. mc_multistate

Corresponds to Chapter 8 ("multi-state survival model"). Requires <code>data</code> to be in mstate's expanded long format (with Tstart, Tstop, status, from, to and covariates); <code>trans</code> is the transition matrix.
Purpose: Fit a multi-state survival model to study the transition risk between several health states (e.g. healthy -> complication -> death), which is closer to the clinical process than a single endpoint. Method: Based on the mstate package; first expand follow-up data into a from-to transition long table, then model each transition separately with <code>coxph()</code>. Arguments: <code>data</code> is the already-expanded multi-state long table (with columns id, Tstart, Tstop, status, from, to, ...); <code>trans</code> is the transition matrix (built by <code>mstate::transMat()</code>, defining which transitions between states are allowed); <code>formula</code> contains the survival object and covariates, and may use <code>strata(trans)</code> to stratify by transition type. Results: Returns a list with <code>model</code> (coxph fit per transition) and <code>msfit</code> (an msfit object for predicting cumulative transition probabilities). Notes: The input must already be in mstate's required long format (not the raw wide table), and the <code>trans</code> codes must match the from/to columns and <code>strata(trans)</code>; a wrong construction leads to "all observations in one group" or no estimable transitions. Depends on mstate (Suggests).

Arguments

transTransition matrix.

Value

A list with <code>model</code> (coxph object), <code>msfit</code> (mstate::msfit object).

Example

# Chapter 8: three-state model (Healthy H -> Complication I / direct Death D)
set.seed(127)
library(mstate)
n <- 150
age <- rnorm(n, 55, 8)
t12 <- rexp(n, .15); t23 <- rexp(n, .20); t13 <- rexp(n, .10)
rows <- list()
for (i in 1:n) {
  if (runif(1) < .6) {
    rows[[length(rows)+1]] <- data.frame(id=i, Tstart=0,      Tstop=t12[i],        status=1, from=1, to=2, age=age[i])
    rows[[length(rows)+1]] <- data.frame(id=i, Tstart=t12[i], Tstop=t12[i]+t23[i], status=1, from=2, to=3, age=age[i])
  } else {
    rows[[length(rows)+1]] <- data.frame(id=i, Tstart=0, Tstop=t13[i], status=1, from=1, to=3, age=age[i])
  }
}
ms <- do.call(rbind, rows)
trans <- transMat(list(c(2,3), c(3), c()), names = c("H","I","D"))
ms$trans <- with(ms, ifelse(from == 1 & to == 2, 1, ifelse(from == 1 & to == 3, 2, 3)))
fit <- mc_multistate(ms, trans = trans, formula = survival::Surv(Tstart, Tstop, status) ~ age + strata(trans))
cat("coxph coefficients:\n")
print(summary(fit$model)$coefficients)
cat("\nmsfit class:", class(fit$msfit)[1], "\n")

39. mc_linear

Corresponds to Chapter 5 ("Linear regression", 5.2 & 5.6). Wraps <code>stats::lm</code> and adds three self-implemented diagnostics: a bootstrap confidence interval for coefficients, variance-inflation-factor (VIF) multicollinearity checks via auxiliary regressions, and the four standard regression diagnostic plots.
Purpose: fit simple or multiple linear regression and automatically produce a reportable coefficient table and diagnostics. Methods: ordinary least squares via <code>stats::lm</code>; on top of it, three self-implemented diagnostics— (1) Bootstrap CI: resample observations with replacement and refit repeatedly, taking empirical quantiles of coefficients as the interval, with no normality assumption (enable with <code>bootstrap > 0</code>); (2) VIF: for each predictor, fit an auxiliary linear regression on the remaining predictors and take 1/(1-R^2) as its variance inflation factor; VIF > 5 usually signals multicollinearity; (3) Four diagnostic plots: residuals vs fitted (non-linearity / heteroscedasticity), normal Q-Q (residual normality), scale-location (whether spread changes with fitted values), Cook's distance (influential points). Arguments: <code>data</code> is a data frame; <code>formula</code> is the model formula (e.g. <code>y ~ x1 + x2</code>); <code>bootstrap</code> is the number of resamples (default 0 = no bootstrap CI); <code>conf_level</code> is the confidence level, default 0.95. Result: returns a list—<code>coef</code> (coefficient table: estimate/SE/t/p/normal CI, plus boot lower/upper if bootstrap on), <code>performance</code> (R^2/adjusted R^2/F statistic/AIC/BIC), <code>vif</code> (VIF per predictor), <code>diagnostics</code> (diagnostic data frame), <code>diag_plots</code> (list of four ggplot objects), <code>plot</code> (main residual diagnostic plot). Note: VIF is computed only for numeric predictors; bootstrap significantly increases runtime, so for very large samples try a small number (e.g. 200) first. This function depends only on base R and ggplot2, no extra packages.

Value

A list with <code>coef</code>, <code>performance</code>, <code>vif</code>, <code>diagnostics</code>, <code>diag_plots</code>, <code>plot</code> (coefficient table, performance metrics, VIF, diagnostics, diagnostic plots and the main residual plot).

Example

# Chapter 5, Sections 5.2/5.6: predict birth weight by mother's age, pregnancy weight, smoking
birthwt <- MASS::birthwt
res <- mc_linear(birthwt, bwt ~ age + lwt + smoke + factor(race),
                 bootstrap = 200)
res$coef                       # coefficient table (with bootstrap CI)
res$performance                # R^2 / adjusted R^2 / AIC / BIC
res$vif                        # variance inflation factor (multicollinearity)
print(res$plot)                # residuals vs fitted diagnostic plot
